# データ

## 保存する情報

| 項目 | 規則 |
| --- | --- |
| URL | 必須、4,096文字まで。元のURLを保持し、1URLを1記録とする |
| タイトル | 任意、500文字まで、改行なし。未設定なら「タイトル未設定（ホスト名）」を表示 |
| タグ | 任意、1個30文字・1記録20個まで。前後の空白を除き、空のタグ・改行は登録しない。全角・半角、英字の大小文字は区別せず、同じなら既存表記を使う。同じ記録内の重複は除く。「卵」と「玉子」など意味での統合はしない |
| 並び順 | 記録ごとの表示順を保存。再起動・更新後も維持する |
| タイトルの入力方法 | 手入力・共有元・自動取得・未設定を区別。手入力したタイトルを自動処理で上書きしないために保存 |
| 管理情報 | 記録を識別するID（UUID）、作成・編集日時。日時はUTC保存、端末の時間帯で表示 |

文字数の上限を超えた場合、手入力なら修正を案内し、取得値なら採用しない。

### URLの扱い

- HTTP・HTTPSの絶対URLのみ受け付ける。
- 認証情報入り、localhost・内部向けホスト名、IPアドレス直書きは拒否する。
- 保存時に到達確認の通信やHTTPSへの書き換えはしない。
- 重複判定では前後の空白、スキーム・ホストの大小文字、既定ポートだけを統一して比較する。比較用のURLは別項目として保存しない。
- パス・クエリ・フラグメントは維持する。短縮URL・通常URL・動画の再生位置違いは別URLとする。

### 保存先と保持

- バージョン1は端末内に保存。一覧・検索の対象は通常のレシピテーブルとする。
- 削除時は記録一式を削除専用のごみ箱テーブルへ移し、削除日時を付ける。通常のレシピテーブルからは削除する。
- 復元時は通常のレシピテーブルへ戻す。移動は一括処理し、失敗時は移動前の状態を保つ。
- ごみ箱は削除日時から30日間保持し、期限後の処理時に完全削除する。
- バージョン1に独自の移行・バックアップ機能はない。紛失・故障・アプリ削除などで失ったデータを独自には復旧できない。iOS標準のバックアップ・移行は利用者の設定や状況による。

## バックアップ（バージョン2以降）

保存記録・並び順・編集に必要な情報を対象とし、ごみ箱・設定・広告同意は含めない。利用者のiCloud容量を使う。

| 操作 | 動作 |
| --- | --- |
| バックアップ | 旧端末で実行し、その時点の記録をiCloudへ保存。成功後に日時・件数を表示する |
| 再バックアップ | 日時・件数を確認して最新1件を置き換える。他端末による更新があれば再確認する |
| 復元 | 新端末で同じApple Accountを使い、日時・件数と現在のデータを置き換えることを確認し、データを検証して一括反映する |
| バックアップを削除 | 設定から確認してiCloud上の保存分を削除。端末内の記録は残す |
| 失敗 | 通信・容量・ログイン状況に応じて理由を表示し、本人が再実行する。バックアップ失敗時は前回分、復元失敗時は現在の端末データを残す |

常時同期は行わず、編集・削除の反映には再バックアップが必要。**旧端末を手放す前に対応版へ更新し、バックアップを完了する。** 実行前に旧端末のデータを失うと、この機能では復旧できない。

CloudKitの[プライベートデータベース](https://developer.apple.com/documentation/cloudkit/ckcontainer/privateclouddatabase)に、バックアップのファイルを[CKAsset](https://developer.apple.com/documentation/cloudkit/ckasset)として、形式の版・日時・件数とともに手動で保存する。CKSyncEngineは使わない。

## 外部からのタイトル取得

| 取得元 | 扱い |
| --- | --- |
| 共有元 | URLと一緒に受け取れたタイトル候補だけ使う。共有文全体をタイトルにせず、追加通信もしない |
| サイト | キユーピー・ミツカン・白ごはん.comの公開レシピに対応。本人の端末からHTMLの`og:title`、なければ`title`を取得。他サイトには取得通信を行わない |

- 優先順は手入力、共有元、自動取得、未設定。本人が空欄にした場合もその指定を守る。取得値は前後の空白を除き、改行を空白にする。
- 自動取得は、手入力・共有タイトルがない記録の新規登録・URL変更後に本体で1回行う。本人が登録したURLだけを対象とする。
- 状態は未取得・取得中・取得済み・非対応・取得失敗。失敗時は既存タイトルを残し、ページが消えても記録は消さない。
- URL変更時は旧URLの共有・取得タイトルを消し、本人のタイトル・タグは残す。旧URLへの取得結果は反映しない。
- 本文・紹介文・写真・動画・アイコン・Recipe情報は抽出・保存しない。タイトルを読み取るために取得したHTMLは一時利用に限る。

## 法的な整理

**本人が選んだ正規公開ページのURL・タイトル・タグを、家庭での料理に使うために本人の端末内へ保存する構成で進める。** 日本法と公開条件に基づく設計判断であり、各社の個別許諾を得たという意味ではない。

| 論点 | 今回の判断 |
| --- | --- |
| URLの保存・リンク | 通常のリンクは原則として著作権侵害に当たらない。本文・画像の転載は行わない。[著作権情報センター・Q12](https://www.cric.or.jp/english/qa/multimedia_qa.html) |
| タイトルの保存 | 一般的な料理名など、ありふれた表現に著作権はなく、題名も通常は保護対象外。創作性がある場合は、本人の操作による端末内保存を私的使用のための複製として扱う。[著作権情報センター](https://www.cric.or.jp/qa/hajime/hajime1.html)・[文化庁・第30条の説明](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/seminar/2025/pdf/94270801_01.pdf) |
| 広告との関係 | アプリの広告収益だけで、利用者による私的な保存が直ちに違法になるとは判断しない。運営者はタイトルを収集・配信せず、保存内容を広告にも使わない |
| サイト規約 | 著作権とは別に取得方法・利用条件を判断する。規約の拘束力は契約への組み入れ等によるが、明示された商用利用制限と争う設計は採らない。[経産省・準則Ⅰ-2-1](https://www.meti.go.jp/press/2024/02/20250212003/20250212003-1r.pdf) |
| 外部送信の公表 | 対象外を前提にせず、公表方式で対応する。送信情報・送信先の事業者名・双方の利用目的を、一覧から容易に開ける日本語の説明に掲載する。外部送信規律は同意取得を一律に求める制度ではない。[総務省FAQ・1-1、1-8、3-2、4-2～4-6](https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu_00002.html) |
| 個人関連情報 | 広告・解析の識別子等が該当し得る。Googleが個人データと結び付ける場合は、同意取得の確認・記録が必要。[Googleの同意取得方針](https://business.safety.google/intl/ja/appi/)を根拠に、提供項目・期間と確認内容を運営者が記録する。[個人情報保護委員会](https://www.ppc.go.jp/all_faq_index/faq1-q8-3/) |
| 広告・解析の同意 | 広告は[UMP](https://developers.google.com/admob/ios/privacy)で必要な同意と変更を扱い、配信不可なら取得・表示を停止する。解析は、適用法・規約で同意が必要な場合は取得後に収集する。UMPだけで解析の同意も満たしたとは扱わない。[解析の設定](https://firebase.google.com/docs/analytics/ios/configure-data-collection) |

運営者・連絡先・利用条件・プライバシー説明を公開する。Google Analyticsの利用とデータの扱いも明示する。[Google Analytics規約・第7項](https://marketingplatform.google.com/about/analytics/terms/jp/)

見出しの反復転載・多数サイトへの営利配信で賠償を認めた[読売見出し事件](https://www.courts.go.jp/assets/hanrei/hanrei-pdf-9350.pdf)も確認した。本アプリは本人の記録だけを扱い、運営者による収集・一覧配信を行わないため、同事件とは利用形態が異なる。

### サイト別のタイトル取得

以下は**アプリから通信して取得する場合**の採用方針。URL保存・手入力・本人操作で共有元から受け取るタイトルの保存は継続する。

| サイト・根拠 | サイトからのタイトル取得 | 判断理由 |
| --- | --- | --- |
| [キユーピー・第1・7項](https://www.kewpie.com/policy/) | 対応 | 私的使用等は規約の禁止対象外。リンクは原則自由。表示に「キユーピー」を併記する |
| [ミツカン・利用案内](https://www.mizkanholdings.com/ja/regulation/) | 対応 | 法で認められる使用は規約の禁止対象外。リンクは原則自由・連絡不要 |
| [白ごはん.com・末尾の表示](https://www.sirogohan.com/) | 対応 | 無断転載・複製の禁止表示はあるが、公開資料に自動取得の個別禁止は確認できず、本人の私的保存に限定して採用 |
| [クラシル・第16条(16)](https://www.kurashiru.com/service_policy) | 見送り | 方法を問わず営利利用を原則禁止。広告付きアプリによる取得について、公開条件から許諾を確認できない |
| [デリッシュキッチン・第12・13条](https://delishkitchen.tv/terms?web=1) | 見送り | 商業利用等を制限。[法人向けレシピAPI](https://biz.delishkitchen.tv/retailhub)はあるが、今回使える一般公開の利用条件は確認できない |
| [Nadia・第9条](https://oceans-nadia.com/terms/top)・[FAQ](https://oceans-nadia.com/terms/faq?page=1) | 見送り | 未承認の営利行為・営利目的のリンクを制限。公式の埋め込みカードも今回のタイトル保存を許諾するものではない |
| [YouTube・利用規約](https://www.youtube.com/static?template=terms&hl=ja)・[API規約Ⅲ.E.4](https://developers.google.com/youtube/terms/developer-policies) | 見送り | HTMLの自動取得は原則制限。公式APIでタイトルは取得できるが、30日以内の更新・削除義務が現在の保存仕様に合わない |

対応範囲は `www.kewpie.co.jp/recipes/`、`www.mizkan.co.jp/ouchirecipe/recipe/`、`www.sirogohan.com/recipe/`・`/sp/recipe/` の公開レシピ。公開規約と自動アクセスの制限を確認して選定した。robots.txtやタイトル欄の存在だけを利用許諾とは扱わない。

見送りは「URL保存が違法」という判断ではない。対応サイトの追加は公式条件または個別許諾を根拠として記録し、バックアップ追加時も保存先を含む利用条件を見直す。規約変更・取得拒否があれば該当サイトからのタイトル取得を停止する。ロゴや公認・提携を示す表現は使わない。

## 外部に送る情報

| 送信先 | 情報・目的 |
| --- | --- |
| 各サイト | タイトル取得・閲覧に必要なURL・IP等。本人のタイトル・タグは送らない |
| Google LLC等（AdMob・UMP） | IP・端末識別子・広告の表示や操作・診断情報・同意状況等。広告配信・効果測定・不正対策・同意管理に使用。非パーソナライズ広告でも送信がある。[SDKの開示](https://developers.google.com/admob/ios/privacy/data-disclosure)・[利用目的](https://business.safety.google/intl/ja/tba-jp/) |
| Google LLC等（Google Analytics） | 画面表示・登録・検索などの操作、アプリ・端末情報、解析用のアプリ識別子、IPから推定する地域等。利用状況の把握と改善に使う。[送信情報の説明](https://support.google.com/analytics/answer/10285841) |
| 運営者（問い合わせ先） | 本人が確認した相談・広告報告と返信先。対応に必要な間だけ保管し、不要になれば削除する。レシピ情報は自動添付しない。[利用目的の明示](https://www.ppc.go.jp/all_faq_index/faq1-q4-17/)・[保管の考え方](https://www.ppc.go.jp/all_faq_index/faq1-q5-4/) |
| Apple（バージョン2以降） | 本人の操作によるバックアップ・復元用のデータ |

保存URL・タイトル・タグ・検索語・記録ID・レシピサイトの閲覧履歴は広告・解析・診断ログへ渡さず、検索履歴も保存しない。

SDKの送信項目・送信先は実装した版と設定で検証し、公開する説明と一致させる。
